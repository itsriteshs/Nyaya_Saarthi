## Root cause and changes
The prior structured response repeated quote/value/certainty/approximation per fact, permitted80 mentions and allowed1600 output tokens. Real Ollama logs showed a request generating663+ tokens at about14tokens/s before the60s request limit cancelled it. That explains the observed timeout/503; the Windows connection-reset callback may be cancellation cleanup, but its exact causal link was not independently established. No global exception handler was added to hide connection errors.

Replaced model wire output with a compact facts object mapping human-readable slot names to arrays of exact original-language quotes. Core fields speed/state/date/road_type/vehicle are mandatory arrays, using[] when absent; other supported fields remain available. Short inputs allow12 populated fields and640 output tokens; long inputs allow40 and1400. Backend expands this small representation into the existing validated entity schema. Typed numeric parsing operates only within a span selected by the SLM, never as a rule-based intake fallback. Source grounding, unsupported-slot rejection, assumptions, conflict handling, normalization and user confirmation remain required. No legal dataset or Guidance grounding check changed.

A brief queue is now10s instead of3s. No automatic rule-based extraction, hidden retry loop or unbounded wait was introduced. The existing frontend100s timeout accommodates queue+backend maximum90s request budget, though unusual overhead can still exceed it. Diagnostic metadata includes actual prompt/output token counts. Short-message runtime response dropped to56 generated tokens in the final probe. Local Llama3.2 remains the default; exactly the two original generative models remain configured.

Compact-schema development exposed poor optional-field assignments and invented mentions. Final schema requires explicit absence for the core fields. Invalid quotes and unsupported unit strings are still rejected per mention, not silently accepted. All exploratory results are archived as compact_*_live.json; intermediate Mistral and JSON-mode experiments were unsuccessful and are not claimed as improvements. No model was replaced; final live success is specifically for default Llama. Final production mode remains Ollama structured-schema output, not the unsuccessful bare-JSON experiment.

A general conservative spelling-normalization step now resolves misspelled relative-day words and can recover a uniquely matching original date word when the model corrected its spelling. Numeric dates are never fuzzy-corrected; ambiguous dates remain unresolved. This let the original yesturday remain preserved while resolving its date. These are date-normalization checks, not scenario phrase overrides.
